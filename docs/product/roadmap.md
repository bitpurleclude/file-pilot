# 治理层路线图

版本：v1.1（2026-10-11）
前置阅读：`vision.md`、`governance-design.md`
说明：本路线图未绑定版本号与发布日期；每阶段进入实施时按仓库 AGENTS.md 约定补更新维护交付物（分支、验收证据、回滚说明）。

## 阶段总览

```
① 登记册与建域查重（地基）
② Inbox 自动处理与周报（人力预算落地）
③ 命名 lint + 逻辑视图（体验增强）
④ 全盘扫描报告（真实数据实战）
```

依赖关系：②③④ 均依赖 ①；③④ 相互独立可并行。

## 阶段 ①：登记册与建域查重

**范围**
- SQLite 新增 `areas` / `projects` 表（走现有迁移机制）；`classification_rules` 增加 project 关联；
- 建域向导 UI（设置页新增 Tab）：创建/认领空号/并入既有域；三级查重（坐标占用 → 名称语义相似 → 内容抽样+LLM 判定）；
- 分类管线改造：plan 的目标从「purpose/自由 project 字符串」改为登记册坐标；LLM 批式/单文件模板注入坐标清单 + NEW 前缀约定 + 枚举校验；
- 保留容器自动创建：`00-Inbox` / `90-Archive` / `99-Temp`；
- **本地决策模型评估 spike**（`decision-models.md` §5）：接入 Laya（Apache 2.0，可本地部署的 System One 决策模型）为影子模式——只记录不下盘，两级分解（先领域后项目）基准实测中文文件名语料；达标（≥90%）即按采纳路径 T2 推进，未达标留管线位继续积累标注。

**验收标准**
- 新建名称与既有域相似时，向导必须呈现查重证据并可一键并入；
- 全部分类结果的目标路径可解析回合法坐标（非法坐标 = 缺陷）；
- LLM stub e2e：注入坐标清单后，模型输出被枚举校验拦截/放行的行为确定可测；
- 决策模型影子模式产出对齐率报告（本地两级分解 vs 云端 LLM 坐标），作为 T2 接管决策依据。

**风险与对策**
- 存量用户已有分类数据：坐标迁移策略（自由 project 字符串 → 半自动映射向导）单独设计，允许双轨过渡一个版本。

## 阶段 ②：Inbox 自动处理与周报

**范围**
- `00-Inbox` 监听/扫描入口；四级管线（程序排除区 → 登记册规则 → LLM 置信分流 → 寄存区）；
- 「未确认」标记与改判交互；30 天衰老自动入位；
- 周报：每周自动生成（新增数 / 自动入位数 / 待确认清单 / 人力决策率），一键批量确认。

**验收标准**
- 模拟 100 个新文件的场景，人工决策次数 ≤ 10（预算指标 ≤ 0.1）；
- 程序排除区文件在管线任何分支下都不产生移动 plan；
- 周报中的每个确认/改判动作走可回滚会话。

**风险与对策**
- 自动入位错误率：初期高阈值（宁多寄存少自动），按改判数据回归调参。

## 阶段 ③：命名 lint + 逻辑视图

**范围**
- lint 规则集 v1（ISO 8601 日期、v01 版本、禁 final、禁空格建议、非法字符）；告警进周报，修复动作走会话；
- 逻辑视图首版（推荐索引视图实现）：规则定义视图（坐标/日期/名称模式）+ 手动圈选；硬约束：零字节复制。

**验收标准**
- 对含 `20261006报告_final2.docx` 类文件名的目录产出确定性告警；
- 任一视图成员的文件在磁盘上仅存在一份（字节级校验）。

## 阶段 ④：全盘扫描报告

**范围**
- 对指定盘符（如 D:\）做只读扫描：目录名称相似度聚类 + 内容抽样比对；
- 输出重叠/重复/交叉报告（疑似孪生、同义目录、跨处同名主题、下载区散布）；
- 报告项可一键转为「建域查重」或「合并重排会话」。

**验收标准（用真实案例做基准）**
- 对开发者的 D 盘扫描，必须命中以下已知案例：`video/` vs `vedio/`（拼写孪生）；`公务员/` vs `公务员考试/`（同主题分阶段）；`毕业设计/` vs `fsor_gloCal/`（同项目散布）；四处下载目录（`download` / `BaiduNetdiskDownload` / `downloadApp` / `msdownld.tmp`）。
- 扫描全程只读（不产生任何移动）。
- 说明：上述案例名来自开发者本机私有盘，仅作本地验收基准；对外分发本文档前须脱敏。
