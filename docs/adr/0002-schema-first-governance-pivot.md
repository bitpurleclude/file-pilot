# ADR-0002: 从「文件分类器」转向「层级治理层」（Schema-First）

## 状态

Accepted（方向性决策；实施排期见 `docs/product/roadmap.md`）

## 背景

项目当前形态是 file-first 的分类管线：文件进来 → 规则/LLM/兜底给出 purpose 与**自由字符串** project → 即兴生成落位路径。真实使用暴露了结构性缺口：

1. `project` 无登记、无记忆——LLM 对同名文件每次编出不同项目名，用户「忘记建过类似文件夹」「两个文件夹交叉」的痛点（如真实 D 盘的 `video/vedio` 孪生、`公务员/公务员考试` 交叉、同一项目散落四处）无任何机制防护；
2. 追问与修正的决策内容仍逐条产生（批量应用能力仅部分覆盖），人工决策量随文件数线性增长，违背人力成本约束；
3. 分类器无法读取 doc/xlsx 内容（仅 txt/md），跨扩展名聚类结构上不可能。

同期完成的领域研究（`docs/product/domain-research.md`）表明：PIM 四十年研究（Malone 1983、Whittaker & Sidner 1996、Bergman 2016、KFTF）与系统史（WinFS 等语义文件系统全线失败）共同指向「用户造轻结构 + 工具治理」是正确形态，且治理闭环在主流产品中空缺。

## 决策

File-Pilot 定位升级为**个人文件层级的治理层**：

1. 引入**登记册**（Johnny.Decimal 式两级编号坐标：领域 10-80 + 域内项目），成为全系统唯一的「去处」表达；
2. 落位从「即兴路径」改为「登记册坐标」；LLM 提示词注入坐标清单，输出做枚举校验（模型认领坐标而非编造名字）；
3. 建立生长协议：出生协议（建域前三级查重）、退役协议（原子归档 `90-Archive`）、Inbox 四级自动管线（程序排除区 → 坐标规则 → LLM 置信分流 → 寄存）+ 周报批量确认；
4. 北极星指标：找得回（溯源查询，基于既有 sessions 数据）；人力决策预算 ≤ 0.1 次/文件；
5. 结构性修订一律编译为可回滚会话（复用既有 apply/rollback 执行器）。

## 对既有决策的取代

- **取代 PLAN.md（2026-02-12 已确认）「M1 默认执行策略：仅 Dry-run；用户确认后手动选择 Move/Copy」**：治理层对 Inbox 高置信文件实行自动入位（打「未确认」标记、整批可回滚），用户确认从「每次移动前」后移为「周报批量复核」——确认粒度由单文件降为批次（见 `vision.md` 原则 2、`governance-design.md` §4）。低置信文件仍寄存、不自动落盘。

## 备选方案（被否决的原因）

- **维持 file-first，仅优化 LLM 提示词**：不解决登记与查重缺口，项目名依旧无锚点，用户核心痛点原样保留。
- **全自动 AI 整理（深度生成分类法）**：与 Bergman 主观属性证据冲突，且 WinFS 一脉四十年验证失败；人失去结构权后不再信任工具。
- **纯搜索方案（Everything 式）**：只解决「找」不解决「放」；Bergman 实验证实空间结构是人脑检索刚需。

## 影响

- 优点：直击用户已明确表达的痛点（忘建、交叉、不可预知）；复用既有大量资产（sessions/rollback、规则引擎、批式 LLM、SQLite 迁移、e2e 基建）；生态位经研究验证为空缺。
- 代价与约束：
  - 分类管线的目标表达从自由字符串改为坐标，是一次破坏性契约变更，需存量数据迁移方案（双轨过渡）；
  - LLM 提示词、规则条件、落位路径三处同步改造，改造面较宽；
  - 登记册引入新的用户上手成本，靠建域向导与默认容器缓解；
  - 阶段 ④ 全盘扫描涉及读取用户真实盘符，须严格只读并明示范围。

详细机制见 `docs/product/governance-design.md`，排期见 `docs/product/roadmap.md`。
